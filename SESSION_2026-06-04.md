# Session 2026-06-04 — GodFather Telegram Overhaul

## Trigger

Live-Test in der Live.Play Telegram Gruppe zeigte mehrere kritische Fehlerbilder:
- GodFather reagierte auf Replies zu **Nova** (anderer Bot), nicht nur auf Eigen-Mentions
- GodFather kopierte Novas Poem-Text (Context Leak aus Chat-History)
- GodFather wiederholte die "Room-aware"-Antwort aus `GOLDEN_EXAMPLES.md` als Template
- Persona-Vorschläge kamen bei Kritik/Korrektur (taub für den Raum)
- GodFather-Prompts zu abstrakt → llama3.1:8b produzierte ausschweifende, repetitive Antworten
- Duplikate in `PERSONAS` dict führten zu inkonsistenten Word-Limits

## 11 Patches

### P1 — Duplicate Persona Keys
- **Problem:** `monkey_mind`, `punk_philosopher`, `nyx` jeweils doppelt in `PERSONAS` dict (erste Version ohne Word-Limit, zweite mit). Python behielt die letzte Definition — die erste war tot.
- **Fix:** Erste 3 Duplikate gelöscht. 7 eindeutige Personas.
- **File:** `handlers/ai.py`

### P2 — Emotion-Tone Check
- **Problem:** `suggest_persona()` feuert nach jeder Antwort — auch bei Kritik/Korrektur ("Copycat", "was soll das", "Bullshit"). Wirkt taub.
- **Fix:** `_is_critical_or_corrective()` Regex-Check vor Persona-Hint. Unterdrückt Vorschlag bei negativem Ton.
- **File:** `handlers/ains.py`

### P3 — GodFather Prompt kürzen + strukturieren
- **Problem:** Prompt war abstrakte Textwand ("Intimität bedeutet...", "Slapstick bedeutet..."). Modell hielt Nuancen nicht.
- **Fix:** Von abstrakten Konzepten zu konkreten Befehlen + Beispiel-Phrasen ("Also hör zu, Choom...", "Kurzfassung:", "Der Plan:").
- **File:** `handlers/ai.py`

### P4 — Word-Limit 200→120
- **Problem:** "Maximal 200 Wörter" zwang Modell zum künstlichen Aufblähen. Mehr Wörter ≠ bessere Antwort.
- **Fix:** Auf 120 Wörter reduziert.
- **File:** `handlers/persona_loader.py`

### P5 — Nova-Kollision (is_reply_to_self)
- **Problem:** `is_reply_to_bot` prüfte ob die Reply an IRGENDEINEN Bot geht. Da Nova auch ein Bot ist, triggerte GodFather auf Nova-Replies.
- **Fix:** `is_reply_to_bot` → `is_reply_to_self` (prüft `reply.from_user.id == context.bot.id`).
- **File:** `handlers/ains.py`

### P6 — num_predict=180
- **Problem:** Kein Hard Cap im Ollama-Request → Modell generierte endlos.
- **Fix:** `options: {"num_predict": 180}` im `/api/chat` Payload.
- **File:** `handlers/ai.py`

### P7 — Golden Example als Template
- **Problem:** `GOLDEN_EXAMPLES.md` enthielt das "Room-aware"-Antwort-Video als wörtliches Beispiel. Modell kopierte es als Template für jede Meta-Frage.
- **Fix:** Verbatim-Text entfernt, nur abstrakte Beschreibung ("A good meta-response acknowledges..."). Warnung "Do Not Copy" war zu schwach für llama3.1:8b.
- **File:** `GOLDEN_EXAMPLES.md`

### P8 — GodFather Prompt mehr Charakter
- **Problem:** P3 war zu aggressiv gestrafft → Antworten klangen generisch/Support-Bot-artig ("Empfang bestätigt, Choom. Systeme laufen auf grün.").
- **Fix:** Wieder mehr Character + konkrete Start-Phrasen. Ton: Fixer, nicht Helpdesk.
- **File:** `handlers/ai.py`

### P9 — Context Priorität
- **Problem:** Bot antwortete auf falsche Context-Fragmente ("freundliches Gesicht oder strenger Kritiker" aus vorherigem Austausch statt auf aktuelle Frage).
- **Fix:** "Antworte NUR auf die letzte Nachricht des Users" im Base Prompt.
- **File:** `handlers/persona_loader.py`

### P10 — num_predict 180→300
- **Problem:** 180 Tokens zwang zu ultrakurzen Antworten. Kein Raum für Substanz.
- **Fix:** Auf 300 Tokens erhöht (zusammen mit P4 Word-Limit 120 Wörter ≈ 200-250 Tokens).
- **File:** `handlers/ai.py`

### P11 — Nyx-Lekage (Prefix-Stripping)
- **Problem:** Modell schrieb manchmal "Nyx.exe: Tiny win logged..." ohne Emoji. `_strip_persona_prefix` erkannte nur Emoji-Varianten → Prefix kam durch.
- **Fix:** Prefix-Liste von 7 auf 16 Patterns erweitert (alle Persona-Namen auch ohne Emoji). Zusätzlich: "Beginne NIEMALS mit Persona-Namen" im Base Prompt.
- **File:** `handlers/ai.py`, `handlers/persona_loader.py`

## Root Cause Analysis

| Symptom | Root Cause | Patch |
|---------|------------|-------|
| Antwortet auf Nova-Replies | `is_reply_to_bot` statt `is_reply_to_self` | P5 |
| Kopiert Nova-Text | Context Leak in Chat History | P5 (weniger false positives) |
| "Room-aware" als Default | Golden Example als wörtliches Template | P7 |
| Persona-Vorschlag bei Kritik | Kein emotionaler Filter | P2 |
| Ausschweifende Antworten | Kein Hard Cap + zu hohes Word-Limit | P6, P4, P10 |
| Persona-Verhalten inkonsistent | Doppelte Dict-Keys mit verschiedenen Limits | P1 |
| Antwortet auf falschen Context | Keine "letzte Nachricht"-Priorisierung | P9 |
| Generische/Support-Bot Sprache | Prompt zu stark gestrafft | P8 |
| "Nyx.exe:" als Prefix | Prefix-Liste unvollständig | P11 |

## Open Issues

- `num_predict` funktioniert im `/api/chat` Endpoint, aber der genaue Wirkungsgrad ist unklar (erster golden-template Test wurde nicht gecuttet).
- 17:55 Nyx-Response könnte Tool-Call gewesen sein (Modell switchte Persona via `persona` Tool), nicht Prefix-Lekage — ist noch nicht vollständig aufgeklärt.
- `llama3.1:8b` ist hart am Limit für die gewünschte Nuance. Sobald das Local-LLM-Setup ein größeres Modell erlaubt (Mistral, Qwen 32B, Llama 3 70B), würden viele dieser Prompt-Engineering-Tricks obsolet.
